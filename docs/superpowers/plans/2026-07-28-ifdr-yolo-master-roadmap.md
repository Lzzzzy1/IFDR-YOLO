# IFDR-YOLO End-to-End Research Roadmap

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 2026-09-07 前形成一套可复现、可证伪、具备会议投稿完整度的道路小目标检测方法与论文，核心贡献是“干预监督的因子化退化后验”，并验证同一后验对尺度路由和不确定性定位的非冗余价值。

**Architecture:** 以 YOLOv8m 为受控基线，先重建可信的 KITTI 数据与 AP40 评测，再通过单因素干预学习分辨率、混叠/噪声、可见性和边界不确定性后验；后验控制 P2–P5 逐位置可靠性路由，并在通过校准门槛后进入期望 IoU 定位。研究采用“诊断先于扩展、筛选实验先于确认实验、失败即收缩”的阶段门机制。

**Tech Stack:** Python 3.11、PyTorch 2.5.1、Ultralytics 8.4.98、NumPy、Pillow/OpenCV、标准库 `unittest`、YAML/JSONL、Git、AutoDL SSH/tmux、KITTI 2D Object Detection。

## 1. 最终交付物

项目结束时必须同时交付以下内容，只有模型权重或一组 mAP 数字不算完成：

1. 可追溯的数据转换、固定划分和数据审计报告。
2. 经过单元测试的 KITTI AP40（Easy/Moderate/Hard）评测器。
3. YOLOv8m、YOLOv8m-P2、P2-BiFPN、普通动态融合等可信基线。
4. 单因素退化干预生成器与配对诊断集。
5. 因子化退化后验、可靠性尺度路由和计算预算约束。
6. 若校准验证通过：退化条件定位损失；若未通过：负结果和收缩版方法。
7. 完整消融、等 FLOPs 对照、三随机种子、效率和失败分析。

9. 论文正文、补充材料、复现实验说明和可投稿图表。

## 2. 研究命题与证据链

### 2.1 论文最多声明三个贡献

1. 面向道路小目标的单因素退化干预与诊断协议。
2. 具有明确退化语义的因子化后验及其 P2–P5 可靠性路由。
3. 同一退化后验对尺度路由和不确定性定位的联合控制及非冗余验证。

P2、BiFPN、WIoU、Inner-IoU、动态融合和概率框本身均为已有思路，只能作为基线或组件，不能单独声明原创。

### 2.2 四条核心假设

| 假设 | 必须提供的证据 | 失败后的处理 |
|---|---|---|
| H1：退化因子可识别 | 因子强度相关性、校准指标、干预特异性和捷径诊断 | 停止 IFDR 主线，不用注意力模块掩盖失败 |
| H2：后验能决定尺度可靠性 | 相对固定 P2/BiFPN/普通门控的 AP、退化曲线和等 FLOPs 优势 | 收缩为退化诊断论文，不声明路由贡献 |
| H3：边界后验能校准定位 | NLL/Brier/ECE、AP40、边界扰动曲线和数值稳定性 | 删除定位贡献，保留路由主线 |
| H4：共享后验具有非冗余价值 | 共享后验优于两个独立控制模块，并控制参数/FLOPs | 改为两个独立模块，不声明统一机制 |

### 2.3 主结果判定

主结果不能只看总体 mAP。至少同时报告：

- KITTI AP40：Car、Pedestrian、Cyclist × Easy、Moderate、Hard；
- Moderate/Hard Pedestrian 与 Cyclist；
- 按原始框高、面积、遮挡和截断分组的 AP/Recall；
- 清晰、降采样、混叠/噪声、遮挡、边界扰动下的性能曲线；
- 参数量、FLOPs、峰值显存、吞吐、延迟和 P2 路由占比；
- 三随机种子均值、标准差和逐种子原始值。

## 3. 数据与评测口径

### 3.1 数据处理原则

- 原始 KITTI 文件只读，所有派生数据写入 `data/processed/`。
- 每张图读取真实宽高，禁止继续使用固定 `1242×375` 归一化。
- 训练主类只使用 Car、Pedestrian、Cyclist。
- Van、Person_sitting、Truck、Tram、Misc 和 DontCare 保留在元数据中，不静默合并。
- 使用固定 ID 文件而不是运行时随机切分。
- 每次数据构建生成清单、SHA256、类别与难度统计和异常报告。

### 3.2 主划分

KITTI 官方训练集没有官方验证划分。主实验采用文献常见的 Chen 划分：3712 张训练、3769 张验证，并在论文中明确写为 common split，而不是 official split。

来源记录：

- Chen et al., MV3D: https://arxiv.org/abs/1611.07759
- OpenPCDet KITTI preparation: https://github.com/open-mmlab/OpenPCDet/blob/master/docs/GETTING_STARTED.md
- 划分文件上游：`traveller59/second.pytorch/second/data/ImageSets/{train,val}.txt`

导入后必须保存下载 URL、文件 SHA256、数量、交集和全集覆盖检查。当前 6732/749 随机划分只保留为历史结果，不进入论文主表。

### 3.3 评测优先级

1. KITTI AP40 是论文主指标。
2. Ultralytics mAP50 和 mAP50–95 是工程辅助指标。
3. 自定义 `<25 px`、面积桶和退化曲线属于扩展指标，必须明确标注非 KITTI 官方指标。
4. AP40 实现需覆盖难度过滤、类相关 IoU、DontCare、Van/Person_sitting 忽略规则和无预测等边界条件。

## 7. 实验分层与算力控制

### 7.1 筛选实验

- 单随机种子；
- 缩短 epoch，但不改变数据划分和评测；
- 用于淘汰明显无效的干预、后验表示和路由形式；
- 不进入论文主表，不据此声明最终提升。

### 7.2 确认实验

- 固定训练预算；
- 至少三个随机种子；
- 保存逐种子指标；
- 关键对照等参数或等 FLOPs；
- 由全新运行产生，不从筛选 checkpoint 续训后冒充独立重复。

### 7.3 运行目录合同

每次正式运行必须生成：

```text
runs/<experiment_id>/
├── config.resolved.yaml
├── data_manifest.json
├── environment.json
├── git_commit.txt
├── metrics.json
├── predictions/
├── train.log
└── weights/
```

`data_manifest.json` 至少记录 split SHA256、标签构建版本、原始数据根目录的只读标识和样本数。`environment.json` 至少记录 Python、PyTorch、CUDA、Ultralytics、GPU 型号和操作系统。

## 10. 风险清单与预案

| 风险 | 早期信号 | 预案 |
|---|---|---|
| 旧标签误差污染结论 | 新旧标签 AP 差异异常 | 所有正式结果从新标签重训 |
| AP40 实现错误 | 合成测试或参考小样本不一致 | 暂停模型开发，先修评测 |
| 因子后验学习类别捷径 | 原图类别可预测退化，干预特异性低 | 配对采样、反事实一致性、位置/类别诊断 |
| P2 带来噪声和显存膨胀 | 清晰场景提升但混叠场景下降 | 预算化可靠性路由，不永久开启 P2 |
| 组合过多导致实验爆炸 | 单种子运行数量持续增长 | 每阶段门只保留 1–2 个入围设计 |
| 期望 IoU 不稳定 | AMP 下 NaN、梯度爆炸、校准不升 | 降级为分析，不放入最终方法 |
| KITTI 数据量小导致方差大 | 单种子提升方向不一致 | 三种子、置信区间、第二数据集趋势验证 |
| 截止日前服务器不足 | 排队或故障超过 24 小时 | 本地先完成全部冒烟；按主表优先级削减扩展 |
| 新颖性被近期工作覆盖 | 检索到高度近似机制 | 收紧贡献或更换主张，不使用绝对原创措辞 |

## 11. 变更控制

以下变化必须先更新设计规范和本路线图：

- 改变主数据划分或 KITTI 评测口径；
- 把第二数据集从扩展改为主数据；
- 改变四个退化因子的语义；
- 用其他检测器替换 YOLOv8m 主基线；
- 把定位模块从可选贡献提升为必选主贡献；
- 新增会使正式实验数量增加超过 20% 的模块。

小范围超参数、测试修复和接口调整只需在对应阶段计划与提交信息中记录。
